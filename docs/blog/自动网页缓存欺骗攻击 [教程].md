01. 漏洞深度解析 (Core Concept)
Web 缓存欺骗 (Web Cache Deception) 的本质是利用服务器与缓存服务器（如 CDN、反向代理）之间对 URL 解析的不一致性。

攻击者通过诱导受害者访问形如 https://example.com/api/user/settings/test.jpg 的链接，使缓存服务器误认为这是一个静态图片从而将其缓存。当攻击者再次访问该链接时，便能绕过权限校验直接读取缓存中的敏感数据。

03. 插件配置自动化 (Autorize Setup)
自动化测试的效率取决于 Autorize 的配置。

1. 注入低权限凭证
我们需要模拟攻击者。在浏览器中以**普通用户（低权限）**登录，捕获其请求。

复制该请求的 Cookie 或 Authorization 字段。

粘贴至 Autorize 选项卡的 Temporary headers 框中。

2. 启用拦截过滤器
为了减少噪音并精准定位目标，请务必进行以下设置：

Check Unauthenticated: 勾选（同步检测未授权访问）。

Interception Filters: 添加 Scope items only（仅检测项目范围内的 URL）。

插件开关: 点击 "Autorize is off" 使其变为 "Autorize is on"。

04. 攻击路径实战 (Attack Pipeline)
第一步：身份隔离
在同一浏览器的不同隐身窗口（或另一浏览器）中，以**高权限（管理员）**身份登录。

第二步：流量触发
作为管理员，正常浏览系统中的所有敏感页面：

个人资料页、订单管理、系统日志、敏感 API 接口。

WCD 特有测试： 在访问上述路径时，手动在 URL 后缀加上 .js, .css, 或 .jpg。

第三步：结果实时监控
Autorize 会实时克隆管理员的每一个请求，并用低权限凭证重发。

05. 结果判读与分析 (Analysis)
Autorize 的结果仪表盘通过颜色直观展示了风险：

状态标记	响应对比结果	漏洞研判
Bypassed! (红色)	低权限与高权限响应一致且成功	高危： 确认存在越权或缓存欺骗
Enforced! (黄色)	低权限请求被拒绝	安全： 权限控制生效
Modified (蓝色)	响应长度不同，但响应码一致	需复核： 可能存在部分数据泄露
06. 总结与防御 (Conclusion)
自动化检测极大地缩短了渗透测试的周期，特别是在处理具有数百个 API 的大型系统时。

核心防御建议：
明确缓存策略： 为所有敏感响应配置 Cache-Control: no-store, private。

路径解析一致性： 确保 Web 服务器与缓存服务器对路径后缀（如 .jpg）的处理逻辑完全一致。

禁用路径映射： 避免类似 Path Mapping 的模糊匹配规则。
